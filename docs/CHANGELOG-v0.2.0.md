## 二、并入的上游能力

### 2.1 `/health` 按区域与模型报可用数（#667）

`/health` 过去只有一个「可用账号数」总数，看不出「国内版还能不能服务这个模型」。
现在按区域与模型分别报可用数：

- `accounts_ready_by_realm` —— 各区域可用数；
- `models_ready` —— 各模型可用数（键级）；
- `accounts_ready_current_realm` —— 当前面板所选区域的可用数；
- `key_accounts_ready` / `key_accounts_bound` —— Key 绑定与可用口径分开。

配套：`count_ready()` 新增 `refresh` 参数，**探针类调用显式要求只读**
（`refresh=False` 时不发起任何网络请求），避免「问一次还剩几个号」变成每个模型一次重试。

### 2.2 池空失败的统一出口（#665 / #666）

两条链路（`/v1/responses`、`/v1/chat/completions`）原先各写一遍池空判断：

- 账本记的码与回给客户端的码**不一致**（账本 502 / 客户端 503），
  按状态码统计 5xx 时「该等」与「该查」混在一起；
- 报错只说「no usable account」，不说**在等谁、等多久**。

现在收成一个出口 `upstream_failure_response()`：**先定状态码、再落账、最后回客户端**，
三个动作用的是同一个码；池空时还会带上「在等哪个账号、等多久」。

> 本项目另有一条 Anthropic Messages 路径，用的是自己的 `_empty_pool_status()` 判据
> （多认一条 `no healthy account` 措辞）。**本版让上游的统一出口改用这条判据**，
> 于是「状态码只有一个决定点」与「三条协议同一判据」两个意图同时成立。

### 2.3 401 真失效不再被当成代理页

网关自己返回 401 时会带 `WWW-Authenticate` 头。以前看到 401 就当凭据失效，
实际上那可能是**网关的登录页**（不是上游的凭据问题）。现在认这个头：凭据真失效才按失效处理。

### 2.4 收费模型撞 6004 也保住「配额用尽」这个事实（#668）

收费模型撞 6004 时，错误分类不再一律降级成「未知错误」，而是保住「配额用尽」这个事实
（对上游现象正确归因，冷却与扣费口径才对得上）。

### 2.5 目录里免费的模型不占积分保底额度（#e38fcb2）

积分保底（`reserve_credits`）本来会把余额压到下限以下的账号挡住，
但**目录里标为免费的模型根本不花这份余额**，不该被它拦。

### 2.6 每日活跃持久化 11140 限制并停止重试

被上游风控（403 / 11140）的账号当天不再按预算反复重试，
限制状态落盘，重启后仍然有效。

### 2.7 面板密码加密异常明确报错（#658）

解释器缺 `hashlib.pbkdf2_hmac` 支持时（例如 Windows 便携版被 Smart App Control 拦了 DLL），
旧实现把计算异常吞成「密码错误」返回 401 —— 用户改了密码却怎么也登不进去。
现在明确返回 500 与排查指引；启动自检与 `/health`、`/panel/status` 暴露 `crypto_ok`，
面板给出提示。新增 `tests/_test_panel_crypto_unavailable.py`。

### 2.8 DSH 文件引用段的 11-128 渠道指纹（#835da5a / #abe6e91）

上游对国内版仍会返回 400 / 11-128，触发面之一是 system 提示里的
「文件引用段」渠道指纹。现在一并中和，并补了覆盖清洗范围的用例。

### 2.9 看板窄屏三处修复

- 活动记录的说明/昵称列分档截断，窄屏不再互相挤压；
- 活动表短标签列不再逐字折行，行高回到单行；
- 下拉不再把「全宽竖排」误判成需要特殊处理，只认显式 `width:100%`。

### 2.10 两个可选开关（**默认关**，升级后行为不变）

| 环境变量 | 作用 |
|---|---|
| `WB_STOP_AT_SSE_DONE=1` | 收到上游 SSE `[DONE]` 后立即停止读取（默认关闭，保持原有行为） |
| `WB_CACHE_HTTP_ERROR_BODY=1` | 缓存首次读取的上游错误正文，供后续读取使用（默认关闭） |

## 三、本版修掉的本项目自己的缺陷

### 3.1 `ready(refresh=False)` 的语义错了：临期账号不该被判「不可用」

**问题**：只读口径下「令牌快到期」原先直接判不可用。
本项目选号路径本来就用 `refresh=False` 扫池（**不**产生网络请求），
真正要用某个账号的那一步（`open_upstream`）会用 `token_needs_refresh()`
给**被选中的那一个**账号刷一次、刷新失败就换号 ——
那么「临期」在选号阶段就该**保留候选**，而不是剔掉。

**后果**：池里所有账号都临期时，刷新这条路被整个堵死，
网关报「无可用账号」(503)，而这些号其实每个都能刷新后正常服务。

**修法**：改成上游语义 —— 只读时**仍算可用**，只是不发起刷新；
刷新仍然「按需、只刷一个」，不会退化成刷新风暴。
副作用是好的：`/health` 的按模型可用数不再少算临期账号。

> 判定依据不是「上游说的」，而是本项目**自己的另一半设计**
> （`open_upstream` 的刷新前置）已经写好了 —— 两半拼起来才自洽。

### 3.2 `count_ready()` 收了 `refresh` 参数却不用

该参数形同虚设：调用方传什么都不影响行为。随上游实现一并修正。

### 3.3 基线里遗留的 10 处中文注释乱码

`wb_accounts.py` / `wb_proxy.py` / `wb_alerts.py` / `wb_update_external.py` 的注释里有
U+FFFD 替换字符 —— v0.1.0 基线从已验证发布包还原时经过一次 GBK 往返。
上游同版本为 0 处，说明是**本项目自带**的。已按上下文逐处补回正确汉字，仓库现 0 处乱码。

### 3.4 「同步上游」的说明原本是错的

README 原先写「`git fetch upstream && git merge upstream/main`」。
本仓库与上游**没有共同祖先**（v0.1.0 基线从发布包还原，提交历史重新起过），
照做会得到一个「全部文件都是新增冲突」的合并。
README 已改成正确做法：以「上游基线提交」为 base 做三方合并、冲突逐处人工裁决。
