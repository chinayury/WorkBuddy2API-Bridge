# WorkBuddy2API-Hub v0.1.0

> 把**多个**腾讯 WorkBuddy / CodeBuddy 账号变成一个 **OpenAI 兼容接口**，
> 并把账号的**成长任务中心**自动化跑完。

- **纯标准库**：31 个 Python 模块 + 1 个单文件前端面板，**零第三方依赖**
- **OpenAI 兼容**：`/v1/chat/completions`、`/v1/models`、`/v1/responses`、`/v1/messages`
- **账号池**：加权选号、冷却退避、模型级冷却、账号级风控识别、并发名额
- **任务自动化**：桌面端 / 网页端指纹事件链点亮「需电脑端」任务，每日 01:00 自动领奖
- **Web 面板**：单文件 vanilla 前端，零外部 CDN
- **自带回归网**：225 个上游套件 + 3 个补丁层测试（每个都带控制组）

---

## 一、它解决什么问题

腾讯 WorkBuddy / CodeBuddy 的账号各自有额度与成长任务，但客户端一次只连一个账号。
直接用官方客户端会遇到：

1. **额度用完就停** —— 没有账号池轮换
2. **成长任务要手点** —— 每天几百积分，不点就丢
3. **客户端限流/风控** —— 单号被打挂就没了

本项目把 N 个账号聚成一个 OpenAI 兼容端点，并顺手把任务中心自动化：

```
   Codex / Claude Code / DSH / Cherry Studio / 任何 OpenAI 兼容客户端
                              │  Bearer <API Key>
                              ▼
        ┌───────────────────────────────────────────────┐
        │  WorkBuddy2API-Hub v0.1.0                     │
        │   · 账号池：加权轮询 / 冷却退避 / 模型级冷却    │
        │   · 协议转换：OpenAI / Responses / Anthropic   │
        │   · 任务引擎：指纹事件链 → 接取 → 上报 → 领奖   │
        │   · 调度器：签到 / 猫猫旅行 / 成长 / 保活       │
        │   · 面板：账号池 / 用量 / 任务 / 设置          │
        └───────────────┬───────────────────────────────┘
                        │  Bearer <账号 token>
                        ▼
              腾讯上游（copilot.tencent.com / www.workbuddy.ai）
```

## 四、运行时模型

| 维度 | 事实 |
|---|---|
| 进程 | **单进程**。`ThreadingHTTPServer`，每连接一线程，`daemon_threads` |
| 连接上限 | `request_queue_size = 128`（请求队列，不是连接数）；**v0.1.0 起每连接 60 秒 socket 超时**（Slowloris 防护） |
| 调度线程 | 3 条常驻 daemon 线程：主循环、窗口探针、额度扫描 |
| 账号级锁 | 每个账号 5 把细粒度锁：额度 / 余额 / 节流 / 刷新 / 落盘，注释明确说明三者互不嵌套 |
| 落盘 | 「唯一临时名 + 原子 replace」，避免两个线程互相截断 |
| 写日志 | 同源脱敏后同时进 stderr 与看板缓冲；可选落 SQLite |
| 子进程 | 仅 1 个：静态加密模块在**其他进程内存**里扫描桌面端密钥（绿色包内置的精简 Python 没有 `multiprocessing`） |
| 更新器 | 独立的 root 服务，面板只能「排队一个 tag」，实际写入由它复核后执行 |

本项目的基线是上游 `d1a8913`。截至 2026-10-26，上游最新为 **v1.8.0**（2026-10-24 发布），
自那以后无新提交，维护状态为**低频维护**。上游明确提示对非官方客户端的识别与拦截持续收紧 ——

## 六、能力边界（诚实声明）

**能做**

- 多账号聚合成一个 OpenAI 兼容端点，自动选号、换号、冷却退避
- 成长任务中心全自动：接取 → 事件上报 → 领奖
- 用量统计与成本估算（按 OpenRouter 公布价折算）
- 面板管理账号、凭据、出口、限额、别名

**不能做 / 有前提**

| 项 | 说明 |
|---|---|
| `unforgeable` 任务 | 需真人操作（如关注公众号满 24 小时），**接口伪造不了**。面板会显示「需人工」并写明原因；真人做完后续轮自动补领 |
| Anthropic Messages | **默认关闭**（不透传 `cache_control`，打开可能白烧积分）。需显式 `WB_ENABLE_ANTHROPIC_MESSAGES=1` |
| 客户端代跑 `web_search` | **默认关闭**。关闭时客户端声明的服务端工具原样透传给上游，上游无执行器 |
| 跨出口回退 | **单向**：国际 → 国内可以，国内 → 国际不行（避免欠费时白烧国内额度） |
| 上游接口 | **全部是逆向所得**，非官方公开 API。客户端升级 / 字段改名 / 加风控都可能让某条链路立刻失效。无 SLA |
| 多副本 | 账号池状态在内存 + 本地文件，**不是分布式锁语义**。多副本会各选各的号，额度与在途限制形同虚设 |
| 凭据落盘 | 账号 token 与 API Key **明文**存在 `accounts/`（上游设计如此，为支持跨机导入）。靠目录权限兜底 |
| 账号级风控 | 上游 403 / code 11140 时**立即停手**，不换号继续打同一台设备（否则设备指纹连坐）。固定 2 小时且持久化 |

## 七、快速开始

```sh
# 1) 取源码
git clone https://github.com/ardeyouxipianyi/workbuddy2api-hub.git && cd workbuddy2api-hub

# 2) 配置面板密码（不要用默认 admin）
cd release
PANEL_PWD=$(python3 -c "import secrets;print(secrets.token_urlsafe(24))")
echo "PANEL_PASSWORD=$PANEL_PWD" > .env && chmod 600 .env

# 3) 构建并启动
docker build -t workbuddy2api-hub:0.1.0 .
docker compose up -d

# 4) 验收
curl -s http://127.0.0.1:8788/health
```

详细步骤见 [DEPLOY-v0.1.0.md](DEPLOY-v0.1.0.md)。
